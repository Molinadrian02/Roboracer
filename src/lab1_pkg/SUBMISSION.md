# Lab 1: Intro to ROS 2

## Written Questions

### Q1: During this assignment, you've probably ran these two following commands at some point: `source /opt/ros/humble/setup.bash` and `source install/setup.bash`. Functionally what is the difference between the two?

Answer: `source /opt/ros/humble/setup.bash` loads the base ROS 2 Humble environment — the packages, libraries, and tools that come pre-installed with the distribution (such as `rclpy`, `rclcpp`, and commands like `ros2`). `source install/setup.bash` loads specifically the packages we have built ourselves with `colcon build` inside our workspace (in this case, `lab1_pkg`), allowing ROS 2 to find our own nodes and executables. The second one depends on the first — we need the base ROS 2 environment loaded before we can use what we built on top of it.

### Q2: What does the `queue_size` argument control when creating a subscriber or a publisher? How does different `queue_size` affect how messages are handled?

Answer: The `queue_size` argument controls how many unprocessed messages can be stored in the queue of a publisher or subscriber before they start being discarded. When the queue is full, the oldest message is dropped to make room for the newest one (FIFO behavior).

A **small** `queue_size` causes the queue to fill up quickly if the node doesn't process messages as fast as they arrive, resulting in more frequent **message loss** — only the most recent messages are kept.

A **large** `queue_size` allows more messages to accumulate without being dropped, but introduces the risk of processing **outdated data**: if the node falls behind, it will end up reacting to messages that no longer reflect the most recent state of the system — something especially dangerous in real-time control systems like an autonomous race car, where reacting to an old steering command can be worse than having no command at all.

### Q3: Do you have to call `colcon build` again after you've changed a launch file in your package? (Hint: consider two cases: calling `ros2 launch` in the directory where the launch file is, and calling it when the launch file is installed with the package.)

Answer: Not always — it depends on how `ros2 launch` is invoked.

If `ros2 launch` is run by pointing directly to the file's path in `src/` (e.g. `ros2 launch /f1tenth_ws/src/lab1_pkg/launch/lab1_launch.py`), rebuilding is not necessary. Since Python launch files are not compiled (they are interpreted directly), any change saved to the file is reflected immediately the next time it runs.

If `ros2 launch` is run by referencing the package by name (e.g. `ros2 launch lab1_pkg lab1_launch.py`), rebuilding **is** necessary. This command looks for the **installed** launch file inside `install/lab1_pkg/share/lab1_pkg/launch/`, which is a copy generated by `colcon build` from the original file in `src/`. If the original file is modified but the package is not rebuilt, `ros2 launch` will keep using the old copy in `install/`, and the changes will not take effect.
